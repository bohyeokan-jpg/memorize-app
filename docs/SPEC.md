# 암기 앱 MVP 개발 지시서

## 1. 프로젝트 목표

Flutter를 사용하여 회원가입 없이 사용할 수 있는 개인용 암기 앱 MVP를 제작한다.

핵심 기능은 다음과 같다.

1. 앱에 기본 제공되는 단어장 선택
2. 사용자가 직접 단어장 파일 업로드
3. 업로드용 샘플 양식 다운로드
4. 단어 학습
5. 정답/오답 기록
6. 간격 반복 방식의 복습
7. 학습 진행률 및 통계
8. 취약 단어 학습
9. 로컬 데이터 저장

서버와 회원가입은 MVP에서 사용하지 않는다.

앱의 핵심 경험은 다음과 같다.

"단어장을 선택한다
→ 학습한다
→ 모르는 단어를 기록한다
→ 잊을 때 다시 보여준다."

# 2. 반드시 지켜야 하는 MVP 범위

MVP에서는 다음 기능만 구현한다.

포함:

- 기본 단어장
- 사용자 단어장
- CSV 업로드
- XLSX 업로드
- TXT 업로드
- 샘플 양식 다운로드
- 파일 업로드 미리보기
- 열 매핑
- 단어 학습
- 정답/오답
- 복습 일정
- 취약 단어
- 학습 통계
- 로컬 저장
- 로컬 알림
- 설정

제외:

- 회원가입
- 로그인
- 서버
- 클라우드 동기화
- 결제

- 발음 평가
- PDF 분석
- 광고

MVP 범위를 임의로 확장하지 않는다.

# 3. 콘텐츠 구조

앱에는 두 종류의 단어장이 존재한다.

## A. 기본 단어장

앱에서 기본으로 제공하는 콘텐츠.

사용자가 별도의 파일을 준비하지 않아도 설치 후 바로 학습할 수 있어야 한다.

MVP 기본 단어장:

- 영어 필수 기초
- TOEIC 기본 단어
- 여행 영어
- 일본어 기초

제공된 assets/wordbooks 파일을 사용한다.

파일:

assets/wordbooks/index.json

assets/wordbooks/english_basic_300.json

assets/wordbooks/toeic_basic_200.json

assets/wordbooks/travel_english_100.json

assets/wordbooks/japanese_basic_100.json

기본 단어장은 코드에 하드코딩하지 않는다.

index.json을 읽어서 동적으로 목록을 만든다.

향후 JSON 파일을 추가하면 새로운 기본 단어장이 앱에 추가될 수 있도록 설계한다.

---

# 4. 사용자 단어장

사용자는 자신의 단어장을 직접 가져올 수 있다.

지원 형식:

- XLSX
- CSV
- TXT

사용자 파일을 가져오면 앱 내부 로컬 DB에 저장한다.

사용자 단어장은 "내 단어장"에서 관리한다.

---

# 5. 업로드 파일 양식

사용자가 반드시 특정 양식만 사용하도록 강제하지 않는다.

앱에서 제공하는 샘플 양식은 권장 형식이다.

권장 XLSX/CSV 구조:

단어 | 뜻 | 예문

예:

abandon | 버리다, 포기하다 | He abandoned the plan.
achieve | 달성하다 | I want to achieve my goal.
accurate | 정확한 | The information is accurate.

최소 필수 컬럼은:

단어
뜻

예문은 선택 사항이다.

---

# 6. 샘플 양식 다운로드

파일 업로드 화면에 반드시 다음 버튼을 제공한다.

[샘플 양식 다운로드]

사용자가 선택할 수 있도록 한다.

- XLSX 샘플 다운로드
- CSV 샘플 다운로드
- TXT 샘플 다운로드

앱 assets/templates에 제공된 파일을 사용한다.

파일:

assets/templates/sample_wordbook.xlsx

assets/templates/sample_wordbook.csv

assets/templates/sample_wordbook.txt

다운로드 방식은 Android에서 사용자가 파일을 저장하거나 공유할 수 있는 방식으로 구현한다.

가능하면 시스템 Share/Save UI를 사용한다.

단순히 앱 내부 파일을 복사하는 것으로 끝내지 않는다.

---

# 7. 샘플 양식 안내

파일 업로드 화면에 다음과 같은 안내를 표시한다.

"처음 사용하시나요?"

[샘플 양식 다운로드]

"첫 번째 열에는 외울 단어,
두 번째 열에는 뜻을 입력해주세요."

그리고 다음과 같이 표시한다.

지원 형식

CSV / XLSX / TXT

예시:

단어 | 뜻 | 예문

---

# 8. 사용자가 다른 형식의 파일을 올리는 경우

사용자가 반드시 샘플 양식을 사용할 필요는 없다.

예를 들어:

English | Korean

abandon | 버리다
achieve | 달성하다

와 같은 파일도 지원한다.

따라서 파일을 분석한 후 사용자에게 열 매핑을 요청한다.

# 13. 데이터 오류

다음 데이터는 오류로 처리한다.

- 단어가 비어 있음
- 뜻이 비어 있음

중복 단어는 기본적으로 사용자에게 알린다.

예:

"중복된 단어 5개가 있습니다."

선택:

[중복 제거하고 가져오기]
[그대로 가져오기]

MVP에서는 중복 제거를 기본값으로 한다.

# 21. 기본 단어장 복사

# 32. 기본 콘텐츠 초기화

앱 최초 실행 시:

assets/wordbooks/index.json

을 읽는다.

각 기본 단어장 JSON을 읽어서 로컬 DB에 등록한다.

이미 등록된 기본 단어장은 다시 등록하지 않는다.

기본 콘텐츠는 앱 업데이트 시 버전 관리할 수 있도록 다음 값을 둔다.

contentVersion

MVP에서는 복잡한 자동 마이그레이션은 구현하지 않는다.

# 37. 데이터 초기화

"모든 학습 기록을 삭제할까요?"

삭제되는 것:

- LearningProgress
- ReviewHistory
- 학습 통계

- 기본 단어장

# 38. 디자인

전체 UI는 깔끔하고 현대적인 학습 앱 스타일.

학습 화면은 특히 집중을 방해하는 요소를 최소화한다.

단어는 크게 표시한다.

뜻은 처음에는 숨긴다.

버튼은 충분히 크게 만든다.

학습 화면에서는 불필요한 메뉴를 최소화한다.

# 42. 오류 처리

파일을 잘못 업로드했을 때 앱이 종료되면 안 된다.

예:

지원하지 않는 파일:

"지원하지 않는 파일 형식입니다."

빈 파일:

"파일에 단어 데이터가 없습니다."

필수 열 없음:

"단어와 뜻에 해당하는 열을 선택해주세요."

잘못된 데이터:

"일부 데이터에 문제가 있습니다."

# 47. 중요한 개발 원칙

기본 단어장과 사용자 업로드 단어장은 반드시 동일한 학습 엔진을 사용한다.

파일 업로드 기능은 특정 양식만 강제하지 않는다.

샘플 양식은 사용자의 편의를 위한 권장 양식이다.

사용자가 다른 컬럼명을 사용하더라도 열 매핑을 통해 가져올 수 있어야 한다.

기본 콘텐츠와 사용자 콘텐츠를 명확하게 구분한다.

학습 데이터는 콘텐츠 데이터와 분리한다.

모든 데이터는 MVP에서는 로컬에 저장한다.

향후 서버 동기화가 가능하도록 Repository 패턴을 사용한다.

MVP에서 불필요한 기능을 임의로 추가하지 않는다.

가장 중요한 것은 "단어장 선택/가져오기 → 학습 → 복습"이라는 핵심 루프를 완성하는 것이다.
